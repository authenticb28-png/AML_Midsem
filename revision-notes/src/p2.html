5Batch Gradient Descent

Big idea: instead of solving the normal equation, start with any θ and repeatedly step downhill on the loss surface. "Batch" = every step uses all training rows.

Why not just use OLS?

  1. Cost: inverting $X^TX$ is $O(p^3)$ — impossible for millions of features.
  2. Invertibility: collinear columns → $X^TX$ singular → no inverse. (GD still runs, but the solution is not unique.)

The update rule

Gradient descent $$\boldsymbol\theta_{\text{new}} = \boldsymbol\theta_{\text{old}} - \alpha\,\nabla L(\boldsymbol\theta_{\text{old}}) \qquad\text{i.e.}\qquad \theta_j \leftarrow \theta_j - \alpha\frac{\partial L}{\partial\theta_j}$$
  • The gradient $\nabla L$ points uphill (direction of steepest increase). Minus → we go downhill. The steeper the slope, the bigger the step.
  • α (learning rate) = step size, a hyperparameter. Too small → slow; too large → overshoots and diverges (loss grows).
  • Simultaneous update: compute all partial derivatives using the old θ, then update all θⱼ together. Updating θ₀ first and using the new θ₀ for θ₁ is wrong.
  • Initialisation: zeros are fine for linear/logistic regression (convex bowl, one minimum).
  • Epoch = one full pass over the data. In BGD, 1 epoch = 1 update.
Derivation — gradient of the MSE

m rows, prediction $\hat y_i = \boldsymbol\theta^T\mathbf x_i = \theta_0 + \theta_1x_{i1} + \dots$ (with $x_{i0} = 1$).

  1. $L(\boldsymbol\theta) = \frac1m\sum_{i=1}^{m}(\hat y_i - y_i)^2$ MSE (squaring makes ŷ − y and y − ŷ the same)
  2. $\frac{\partial L}{\partial\theta_j} = \frac1m\sum_i 2(\hat y_i - y_i)\cdot\frac{\partial\hat y_i}{\partial\theta_j}$ chain rule on each squared term
  3. $\frac{\partial\hat y_i}{\partial\theta_j} = x_{ij}$ in $\theta_0 + \theta_1x_{i1} + \dots$ only the θⱼ term contains θⱼ, and its coefficient is $x_{ij}$
  4. $\boxed{\frac{\partial L}{\partial\theta_j} = \frac2m\sum_{i=1}^{m}(\hat y_i - y_i)\,x_{ij}}$ for θ₀ the "x" is 1, so it is just $\frac2m\sum(\hat y_i - y_i)$
  5. Stack all j into a vector: $\boxed{\nabla L = \frac2m X^T(X\boldsymbol\theta - \mathbf y)}$ row j of $X^T$ times the residual vector = $\sum_i x_{ij}(\hat y_i - y_i)$

Some books use $L = \frac{1}{2m}\sum(\cdot)^2$; then the 2 cancels and $\nabla L = \frac1m X^T(X\boldsymbol\theta - \mathbf y)$. Same minimum, only the step size changes.

Worked: one BGD epoch on (1,2), (2,4), (3,6), (4,8), θ = (0, 0), α = 0.1
  1. Predictions with θ = (0,0): all 0. Errors $\hat y - y$ = −2, −4, −6, −8.
  2. Course-quiz convention (average of e and e·x, no 2): $g_0 = \frac{-2-4-6-8}{4} = -5$; $g_1 = \frac{(-2)(1) + (-4)(2) + (-6)(3) + (-8)(4)}{4} = \frac{-60}{4} = -15$.
  3. Update: $\theta_0 = 0 - 0.1(-5) = 0.5$, $\theta_1 = 0 - 0.1(-15) = 1.5$ → θ = (0.5, 1.5) after one update.
  4. With the worksheet's full MSE (factor $\frac2m$) the gradient doubles to (−10, −30) and θ = (1, 3). Check which convention the question/options use.
Worked: lab model y = w·x (no bias)

x = [1, 2, 3], y = [2, 4, 6], w = 0, lr = 0.01, $dw = \text{mean}\big(2(wx_i - y_i)x_i\big)$.

Terms: $2(0-2)(1) = -4$, $2(0-4)(2) = -16$, $2(0-6)(3) = -36$ → mean = −56/3 = −18.667 → $w = 0 - 0.01(-18.667) = 0.1867$. Repeat for each epoch; it converges to w = 2.

Learning rate and convergence

Why a big α diverges (1-D bowl $L = a\theta^2$)
  1. $\frac{dL}{d\theta} = 2a\theta$ → $\theta_{\text{new}} = \theta - \alpha\cdot2a\theta = (1 - 2a\alpha)\,\theta$
  2. Each step multiplies θ by $(1 - 2a\alpha)$. It shrinks toward 0 (the minimum) only if $|1 - 2a\alpha| < 1$, i.e. $0 < \alpha < 1/a$.
  3. $\alpha > 1/a$ → $|1 - 2a\alpha| > 1$ → θ jumps across the bowl further each time → diverges. Between $\frac1{2a}$ and $\frac1a$ it zig-zags but still converges.
  • Choose α on the validation loss (never the test set). Typical grid: 0.001, 0.01, 0.1, 1.
  • Feature scaling: features on very different scales (attendance 70–100 vs hours 1–5) make a stretched bowl; the large feature gets huge gradients, so α must be tiny and progress is slow (zig-zag). Standardise first.
  • Convex MSE + suitable α → BGD reaches the same global minimum as OLS.
BGD pros / cons

+ exact gradient, smooth stable path, deterministic. − one update needs a full pass: high cost per update, memory & I/O pressure (data bigger than RAM), slow feedback (can't adapt quickly, e.g. fraud), redundant work (near-identical rows).

⚠ Exam traps
  • Subtract α × gradient (adding goes uphill). If you write the error as y − ŷ, the sign flips.
  • BGD does not invert $X^TX$.
  • In L4 "m" = number of features; in L5 "m" = number of rows. Read carefully.

6Stochastic & Mini-Batch Gradient Descent

Big idea: BGD waits for all m rows before one step. SGD steps after every single row; mini-batch steps after every b rows.

The three update rules $$\textbf{BGD: } \boldsymbol\theta \leftarrow \boldsymbol\theta - \alpha\frac1m\sum_{i=1}^{m}\nabla J_i \qquad \textbf{SGD: } \boldsymbol\theta \leftarrow \boldsymbol\theta - \alpha\nabla J_{i_t} \qquad \textbf{Mini-batch: } \boldsymbol\theta \leftarrow \boldsymbol\theta - \alpha\frac{1}{|B|}\sum_{i\in B}\nabla J_i$$

Per-row gradient (½-squared loss, e = ŷ − y): $\nabla J_i = [\,e_i,\ e_ix_i\,]$ for (θ₀, θ₁).

Cost per epoch is the same $O(md)$ for all; SGD just makes m times more (cheaper, noisier) updates. b = 1 → SGD; b = m → BGD.

Why SGD works — "unbiased but noisy"

SGD randomises which sample $i_t$ is used. Averaged over the random choice: $\mathbb E[\nabla J_{i}] = \frac1m\sum_i \nabla J_i = \nabla J$. So on average it points the right way (unbiased), but each single step can be off (high variance). Consequences:

  • The loss can go up after one step; judge the trend over many steps.
  • With a fixed α it keeps bouncing near the minimum; a decaying α lets it settle.
  • Noise can help escape shallow local minima / saddle points (non-convex problems).
  • Shuffle every epoch, otherwise consecutive updates follow the data's ordering pattern instead of the true signal.

⚠ Exam traps
  • Summing the gradients over all samples and updating once after the loop = BGD, not SGD.
  • Batch sizes 32/64/128 are chosen for GPU efficiency, not because maths requires them.
  • Most stable = BGD, noisiest = SGD; mini-batch = the best overall balance.
  • Lab versions use the full squared error: $w \leftarrow w - \alpha\cdot2(wx_i - y_i)x_i$, seed 42, shuffle the indices each epoch.

7Evaluation Metrics

Big idea: the training loss helps the optimiser; metrics judge the model on data it hasn't seen. Here the residual is $e = y - \hat y$.

Regression metrics

Regression formulas
$$\text{MAE} = \frac1n\sum|y_i - \hat y_i|$$ $$\text{MSE} = \frac1n\sum(y_i - \hat y_i)^2$$ $$\text{RMSE} = \sqrt{\text{MSE}}$$
$$\text{MAPE} = \frac{100}{n}\sum\frac{|y_i - \hat y_i|}{|y_i|}$$ $$R^2 = 1 - \frac{\text{RSS}}{\text{TSS}}$$ $$R^2_{adj} = 1 - (1 - R^2)\frac{n-1}{n-p-1}$$

$\text{RSS} = \sum(y_i - \hat y_i)^2$ (model's error), $\text{TSS} = \sum(y_i - \bar y)^2$ (error of always predicting the mean of the actual y). p = number of features (no intercept).

Why adjusted R² exists (the logic chain)

Add any feature → OLS can fit a little noise → RSS falls a little → $R^2 = 1 - \text{RSS}/\text{TSS}$ rises regardless of the reason → R² falsely reports improvement → a fair metric must penalise complexity → adjusted R². Its factor $\frac{n-1}{n-p-1}$ grows with p, so a useless feature lowers it.

e.g. 60 rows: model 1 (p = 3, R² = 0.750) → adj 0.7366; model 2 (p = 5, R² = 0.758) → adj 0.7356 → prefer model 1.

Classification metrics

sklearn: rows = actual, columns = predicted; confusion_matrix(...).ravel() → tn, fp, fn, tp.

Classification formulas
$$\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}$$ $$\text{Precision} = \frac{TP}{TP + FP}$$ $$\text{Recall (TPR)} = \frac{TP}{TP + FN}$$
$$F_1 = \frac{2PR}{P + R} = \frac{2TP}{2TP + FP + FN}$$ $$F_\beta = \frac{(1+\beta^2)PR}{\beta^2P + R}$$ $$\text{Specificity} = \frac{TN}{TN + FP},\ \ \text{FPR} = 1 - \text{spec}$$
  • Precision = of the ones I predicted positive, how many were right → matters when false alarms are costly (spam folder hiding real mail).
  • Recall = of the actual positives, how many I caught → matters when misses are costly (fraud, cancer).
  • F1 = harmonic mean (punishes imbalance between P and R); ignores TN. β = 2 favours recall; β = 0.5 favours precision.
  • Accuracy lies on imbalanced data — check per-class recall.
Worked: TP = 40, FP = 10, FN = 20, TN = 30

Accuracy = 70/100 = 0.70. Precision = 40/50 = 0.80. Recall = 40/60 = 0.667. F1 = 2(0.8)(0.667)/(1.467) = 0.727 (check: 80/110). Specificity = 30/40 = 0.75.

Multiclass averaging

Averages $$\text{Macro} = \frac1K\sum_k M_k \qquad \text{Weighted} = \frac{\sum_k n_kM_k}{\sum_k n_k} \qquad \text{Micro: pool all TP, FP, FN first}$$
  • Macro: every class gets an equal vote → use when all classes are equally important (exposes a weak small class).
  • Weighted: big classes count more (by support n_k).
  • Micro: for single-label multiclass, micro-P = micro-R = micro-F1 = accuracy.

e.g. class F1 = 0.9, 0.6, 0.3 with supports 50, 30, 20: macro = 1.8/3 = 0.60; weighted = (45 + 18 + 6)/100 = 0.69. Model A F1s (0.95, 0.90, 0.20) → macro 0.683; model B (0.75, 0.75, 0.75) → macro 0.75 → B is better if all classes matter equally.

ROC and AUC (extra)

Lowering the threshold → more positives → TPR ↑ and FPR ↑. ROC = TPR vs FPR over all thresholds. AUC = 1 perfect, 0.5 random; AUC = P(a random positive scores higher than a random negative).

⚠ Exam traps
  • Accuracy = (TP + TN)/total, not (TP + FP)/total.
  • MAPE divides by the actual y. TSS uses the mean of the actual y.
  • Adjusted R² denominator is n − p − 1. sklearn MAPE returns a fraction (×100 for %).
  • Two models with the same MAE can have different MAPE (errors on small actual values cost more %).

8Polynomial Regression & Assumptions of Linear Regression

Polynomial regression

Big idea: a straight line can't follow a curve, so create new features x², x³, … and run ordinary linear regression on them.

Polynomial model $$\hat y = \beta_0 + \beta_1x + \beta_2x^2 + \dots + \beta_nx^n \qquad \phi(x) = (1, x, x^2, \dots, x^n)$$

Design matrix columns: 1, x, x², … → still $\boldsymbol\beta = (X^TX)^{-1}X^T\mathbf y$. Still linear regression because it's linear in the β's. Degree n, 1 feature → n + 1 columns; turning points ≤ n − 1. Degree 2 on 2 inputs → 1, x₁, x₂, x₁², x₁x₂, x₂² = 6 columns.

A curve in (x, y) becomes a plane in (x, x², y) space — the model fits a flat plane to lifted data. Higher degree → lower training error always, but too high a degree overfits (wiggly curve through noise, large test error). Pick the degree on validation data. Scale x before using high powers (x⁸ explodes).

Lab rule ("Polynomial Detective"): underfit if train > 0.3 and test > 0.3 and |train − test| < 0.05; else overfit if train < 0.1 and test > 0.15; else good. Best degree = lowest test MSE (tie → smallest degree).

The 5 assumptions (check with residuals $e = y - \hat y$)

Funnel = heteroscedasticity; U-shape = non-linearity. Normality is about the residuals, not the features.

Proof — perfect multicollinearity makes XᵀX singular
  1. Suppose column 3 = column 1 + column 2. Then $X\mathbf c = \mathbf 0$ for $\mathbf c = (1, 1, -1)^T \ne \mathbf 0$. col1 + col2 − col3 = 0 in every row
  2. $X^TX\mathbf c = X^T(X\mathbf c) = X^T\mathbf 0 = \mathbf 0$ matrix multiplication can be regrouped
  3. If $(X^TX)^{-1}$ existed: $\mathbf c = (X^TX)^{-1}\mathbf 0 = \mathbf 0$ — contradiction, since $\mathbf c \ne \mathbf 0$. multiply step 2 by the inverse
  4. So $X^TX$ has no inverse: det(XᵀX) = 0 and OLS has no unique solution.

Example: $X = \begin{bmatrix}1&1&2\\1&2&3\\1&3&4\end{bmatrix}$ (col3 = col1 + col2). A scaled copy (x₂ = 2x₁, °F = 1.8°C + 32) works the same way.

Formal tests (extra) $$\text{VIF}_j = \frac{1}{1 - R_j^2} \qquad DW = \frac{\sum_{t=2}^{n}(e_t - e_{t-1})^2}{\sum_{t=1}^{n}e_t^2}\in[0,4]$$

$R_j^2$ = R² from regressing feature j on the other features. VIF > 10 = serious (R²ⱼ = 0.9 → VIF 10). DW ≈ 2 = no autocorrelation; < 2 positive; > 2 negative. e.g. residuals 1, −1, 1, −1: numerator 4 + 4 + 4 = 12, denominator 4 → DW = 3.

⚠ Exam traps
  • Multicollinearity hurts the coefficients (interpretation) more than prediction.
  • Autocorrelation is about the residuals over time; multicollinearity is about features vs features.
  • Create x² from the training x and apply the same transform to the test x.
